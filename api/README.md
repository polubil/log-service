# Web API сервис
Реализован асинхронный сервис на FastAPI.
Сервис принимает строку следующего формата ```{IP адрес} {HTTP method} {URI} {HTTP status code}```, например ```192.168.1.1 GET /api/users 200```
Далее происходит парсинг строки, сохранение данных в PostgreSQL с присвоением уникального идентификатора и времени создания записи.
### Технологии
Python 3.14, FastAPI, Pydantic, Pydantic-settings, PostgreSQL (asyncpg) 
Для хранения настроек и работы с переменными среды была выбрана библиотека Pydantic-settings, так как сам Pydantic уже используется в проекте для моделей и валидации запросов. Валидацию переменный окружения проводим с помощью Pydantic-settings. 

Для работы с PostgreSQL был выбран драйвер asyncpg - по бенчмаркам он быстрее популярных psycopg2 (синхронный, исключаем сразу) и psycopg3 (есть AsyncConnection, но медленнее asyncpg в ~5 раз). Asyncpg из коробки асинхронный, как и FastAPI, что подходит под наш стэк. 
Был реализован простой управляющий класс DB, который создавал пул подключений к базе, подключался и отключался, выполнял требуемые запросы. FastAPI работает с этим классом-оберткой Connection-per-Request через механизм Dependencies. Подключение выбирается из пула, а после в него возвращается. 

В проектах побольше принято использовать ORM, такие как SQLAlchemy, потому-что они упрощают работу с базой и делают её более безопасной, в том числе защищают от инъекций. В силу того, что в проекте всего 1 модель и 3 запроса к базе (1 на создание и 2 на  чтение), а в ТЗ нет прямого требования использовать какую-либо из ORM, было принято решение не тянуть в него громоздкую ORM, не прописывать для нее модели, заниматься миграциями Alembic. Я умею это делать, но осознанно решил в этом проекте пройти более простым путем в целях избежания overengeeniring. 

### Endpoint'ы
#### POST /api/data
Реализована фильтрация по методу (множественный выбор), по статус коду (множественный выбор) и по дате (больше/меньше/в диапазоне)
Request:
```
{
    "log": "192.168.1.1 GET /api/users 200"
}
```
Response:
```
Status  Описание
201     Лог успешно сохранён
400     Некорректный формат данных
500     Внутренняя ошибка сервиса
```
#### GET /api/data
Request:
```
GET /api/data?method=GET&status_code=201&lt=2025-01-01T12:00:00&gt=2025-01-01T10:00:00&limit=10&offset=10
```
| Поле | Значения | По умолчанию | Описание |
|-------|-----|------|------|
| method | GET, POST, PUT, PATCH, OPTIONS, HEAD, DELETE | None | Фильтрация по методу |
| status_code | int | None | Фильтрация по http статус коду |
| lt | isoDateString | None | Верхняя граница фильтра по дате создания записи |
| gt | isoDateString | None | Нижняя граница фильтра по дате создания записи|
| limit | int | 10 | Вернется не больше limit строк |
| offset | int | 0 | Смещение от начала |

Response:
```
[
    ...,
    {
    "id": "uuid",
    "created": "2025-01-01T11:00:00",
        "log": {
            "ip": "192.168.1.1",
            "method": "GET",
            "uri": "/api/users",
            "status_code": 201
        }
    },
    ...
]
```

#### GET /api/stats
Допустима фильтрация по дате.
Request:
```
GET http://localhost:8000/api/stats?gt=2025-01-01T12:00:00&lt=2025-01-01T14:00:00
```
| Поле | Значения | По умолчанию | Описание |
|-------|-----|------|------|
| lt | isoDateString | None | Верхняя граница фильтра по дате создания записи |
| gt | isoDateString | None | Нижняя граница фильтра по дате создания записи|

Response:
```
GET /api/stats
{
    "methods": {
        "GET": 120,
        "POST": 95,
        "PUT": 12
    },
    "status_codes": {
        "200": 210,
        "404": 15,
        "500": 2
    }
}
```
