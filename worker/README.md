### Сервис фоновой обработки

Сервис периодически (каждые `WORKER_REQUESTS_DELAY_S` секунд) выполняет GET-запросы к Web API сервису и сохраняет полученные данные в csv файл, примонтированный как Docker Volume.

Реализованы:
запуск по таймеру;
сохранение результатов в общий файл;
возможность запуска нескольких экземпляров сервиса одновременно с использованием одного разделяемого файла.

#### Процесс работы

1. Сервис проверяет существование файла. При отсутствии создает его.
2. Захватывается эксклюзивная блокировка на csv-файл с данными с помощью `data.lock` файла.
3. Читается последняя строка csv-файла, извлекается поле created. Это поле будет использоваться как нижняя граница фильтра при запросе новых данных.
4. С помощью асинхронного HTTPX клиента выполняется запрос новых данных. Сервис запрашивает `WORKER_REQUEST_MAX_ROWS` (100 по умолчанию) новых записей каждые 10 секунд.
5. Файл .csv обогощается новыми данными.
6. Блокировка с файла снимается, сервис спит `WORKER_REQUESTS_DELAY_S` секунд.

#### Комментарий

1. Благодаря блокировке учитывается требование к возможности запуска нескольких сервисов одновременно. Конкурентный доступ к файлу регулируется блокировкой, которая покрывает как чтение, так и запись в файл, что снижает нагрузку на базу и не требует дополнительной дедупликации после получения данных из Web API сервиса.
2. Блокировка реализована с помощью стандартной библиотеки - `fcntl.flock` и работает только на Unix системах. Исходя из требования "Использовать Docker для каждого сервиса", было принято допущение, что сервис будет запускаться исключительно в контейнерах под unix. В репозитории используются Dockerfile с базовым образом Ubuntu.
3. csv формат выбран как наиболее простой для чтения и записи, не предполагающий множественных структурный конструкций, как, например, JSON.

#### Выходной файл.

Выходной файл создается в каталоге `./data/`
Имя выходного файла задается переменной окружения `WORKER_DATA_FILENAME` и указывается без расширения. По умолчанию файл будет называться `data.csv`
Выходной файл выглядит следующим образом:

```
id,created,ip,method,uri,status_code
"7b326573-da32-4e80-b8a5-2d0effd637ad","2026-07-06T17:56:04.401815","194.236.126.249","OPTIONS","/login","400"
"a580f6e6-d030-4d2b-aef5-25081de36c90","2026-07-06T17:56:07.616950","117.136.70.67","DELETE","/api/users","419"
"e49afc0c-7145-41b7-bd67-a1a19e9c4172","2026-07-06T17:56:13.284701","30.74.200.235","PUT","/login","404"
```

#### Список переменных окружения

```
WORKER_REQUESTS_URL=http://api:8000/api/data
WORKER_REQUESTS_DELAY_S=10
WORKER_REQUESTS_MAX_ROWS=100
WORKER_DATA_FILENAME=data
```
