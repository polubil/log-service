### Клиентский сервис
Сервис генерирует строки формата ```{IP адрес} {HTTP method} {URI} {HTTP status code}``` и отправляет их в Web API сервис через POST-запросы.

#### Реализовано:
##### 1. работа в N потоков;
Реализована с помощью threading
Для обеспечения параллелизма были выбраны потоки, так как сервис не CPU-bound, а с IO-операциями потоки справляются хорошо, даже с учетом GIL.
Начиная с Python 3.13 есть возможность запуска Python без GIL, free-threaded, но я использовал обычную сборку 3.14 с GIL.
Количество потоков задается переменной окружения ```CLIENT_WORKERS```, по умолчанию 2.
##### 2. случайная задержка между запросами до M миллисекунд;
Задается с помощью переменой окружения ```CLIENT_MAX_DELAY_MS```, по умолчанию 1000.
##### 3. все отправленные сообщения логируются в файл.
Используется стандартная библиотека, модуль logging. С помощью несложной конфигурации (```src/logger.py```) все отправленные запросы логируются в файл logs.log. Модуль logging потоко-безопасен по умолчанию, поэтому мне показалось это хорошим выбором для использования в многопоточной архитектуре. 

#### Переменные окружения

```
CLIENT_REQUESTS_URL=http://api:8000/api/data
CLIENT_WORKERS=10
CLIENT_MAX_DELAY_MS=1000
CLIENT_HTTP_TIMEOUT=2
```
